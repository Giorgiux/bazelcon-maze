# Maze

A small, self-contained Bazel + Java project: a playable browser maze game whose
build graph doubles as a sandbox for build-performance questions, where the
critical path is, how much parallelism is available, and when work is being redone.

Levels are generated at build time by a seeded Java maze generator, assembled into
a static site, and played in the browser. No runtime server, no third-party
dependencies.

## Build and run

Prerequisites: Bazel (the version is pinned in `.bazelversion`, so `bazelisk`
picks it up automatically). The Java toolchain is hermetic (Bazel fetches a remote
JDK), so no local JDK is required.

Build everything:

    bazel build //...

Build and play the game:

    bazel build //game:site
    open bazel-bin/game/site/index.html

The game runs from `file://`, so there is nothing to serve.

Run the tests:

    bazel test //...

## Layout

- `engine/` core maze engine (generation + dependency-free JSON), one Java library.
- `tools/mapgen/` CLI wrapper around the engine.
- `levels/` individual levels, generated by genrules.
- `pipeline/` a staged generation pipeline that produces the campaign level.
- `web/` the static front end (HTML, CSS, JS).
- `game/` final assembly: level JSON into `levels.js`, then the staged site.
- `tests/` engine stress test.
- `docs/optimization-decision-tree.md` the build-optimization framework this repo is built around.
- `.claude/skills/optimal_build_check/` a skill that measures how fast a build is versus how fast it could be, and explains the gap.

## Notes

The graph intentionally exercises the shapes that matter for build speed: a serial
pipeline, a high fan-out core library, a heavy leaf target, and optional build
stamping. `docs/optimization-decision-tree.md` walks through diagnosing them.
